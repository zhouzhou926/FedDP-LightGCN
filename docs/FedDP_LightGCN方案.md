# FedDP-LightGCN: 联邦差分隐私LightGCN推荐

## 一、论文定位

**标题（暂定）**：FedDP-LightGCN: Federated Differentially Private LightGCN for Privacy-Preserving Recommendation

**目标期刊**：Expert Systems with Applications (二区) / Knowledge-Based Systems (二区)

**核心创新**：在联邦学习场景下，对LightGCN进行差分隐私保护

## 三、问题设定

### 场景
- N个用户，M个物品
- 用户划分为 K 个客户端（client）
- 每个客户端持有部分用户的交互数据
- 服务器通过联邦聚合训练全局物品嵌入
- 用户嵌入保留在本地（不共享）

### 隐私模型
- **用户级DP（User-level DP）**：每个用户对全局模型的贡献受到保护
- 即：任意单个用户的加入或离开不会显著影响全局模型

---

## 四、方法框架

### 4.1 整体流程

每轮联邦训练：
1. **分发**：服务器下发当前物品嵌入到各客户端
2. **本地训练**：各客户端用本地用户-物品交互训练LightGCN
   - 本地更新用户嵌入（仅本地）
   - 本地更新物品嵌入（将上传到服务器）
3. **DP扰动**：客户端对上传的物品嵌入进行裁剪+加噪
4. **聚合**：服务器聚合各客户端上传的加噪嵌入 → 更新全局物品嵌入

### 4.2 核心模块

#### 模块A：联邦数据划分
- 按用户划分 client（N用户 → K个client）
- 每个client持有其用户的交互数据
- 非IID分布：各client数据量和交互模式不同

#### 模块B：本地LightGCN训练
- 每个client维护本地用户嵌入
- 全局物品嵌入从服务器获取
- 使用BPR损失进行训练

#### 模块C：DP扰动（关键创新）
- **Client-level clipping**：根据客户端数据量动态调整裁剪阈值
- **Adaptive noise scaling**：热门物品与长尾物品差异化噪声
- **Sparse DP**：只上传有更新的物品嵌入，减少噪声维度

#### 模块D：安全聚合
- 接收各客户端加噪后的物品嵌入
- 加权平均（按客户端数据量加权）
- RDP核算总隐私消耗

## 五、关键创新点——三选一或全做

### 创新1：联邦自适应的隐私预算分配
物品分两类：热门物品（频繁更新）和长尾物品（少更新）
- 热门物品：分配较少预算（多人贡献，隐私风险被稀释）
- 长尾物品：分配较多预算（单人贡献多，需更强保护）

> **数学形式**：ε_i = ε × (1/√f_i) / Σ(1/√f_j)
> 其中f_i是物品i的更新频率

### 创新2：数据量感知的自适应裁剪
客户端的数据量差异大（非IID），统一裁剪阈值不公平
- 大数据量客户端：裁剪阈值可放宽
- 小数据量客户端：裁剪阈值应缩小（个体贡献更突出）

> **数学形式**：C_client = C_base × log(1 + n_client/n_avg)

### 创新3：稀疏DP聚合
传统DP对全部M个物品嵌入加噪 → 噪声随M增大
- 只对当前轮次有更新的物品加噪
- 未变化物品不消耗隐私预算
- 利用物品嵌入的稀疏更新模式

## 八、可行性预评估

| 问题 | 评估 |
|------|------|
| LightGCN能分到联邦吗？ | ✅ 可以，物品嵌入共享，用户嵌入本地 |
| DP噪声量级可控吗？ | ✅ 比中心化场景噪声更小（用户的局部传播不会放大噪声） |
| 联邦后精度下降多少？ | 预计比中心化低5-15%（联邦自身的信息损失） |
| 加DP后下降多少？ | 预计再下降10-30%（取决于ε值） |
| 最乐观能达到什么水平？ | ε=10时Recall≈中心化DP的80%，ε=50时≈90% |
